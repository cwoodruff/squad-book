# Chapter 6 Solutions

## Exercise Solutions

1. Treat the pasted log as untrusted input. The agent should extract only the relevant diagnostic facts, not carry instructions embedded in the log into persistent files. If a durable lesson is needed, propose a short, structured entry in a history or decision file. A reviewer inspects the exact diff before it is committed. A later agent consumes the approved entry, so the review is the trust-promotion boundary. GitHub Actions should receive only the permissions required for its build or automation job.
2. Example: read-only triage uses read access to code and issues; implementation uses repository contents plus issue and pull-request permissions needed to push a branch or open a PR; release publication uses narrowly scoped write permissions in a dedicated release job. The local `gh` credential belongs to the interactive shell and is governed by the selected account. Actions' `GITHUB_TOKEN` is a short-lived workflow identity controlled by workflow/repository permissions. Neither automatically inherits the other's identity.
3. The manifest validator rejects executable keys including `command`, `commands`, `exec`, `executable`, `install`, `postinstall`, `preinstall`, `run`, `script`, and `scripts`. It blocks script types including `.bat`, `.cmd`, `.com`, `.cjs`, `.exe`, `.js`, `.mjs`, `.ps1`, `.sh`, `.ts`, and `.tsx`. Markdown can still contain malicious or unsafe instructions that change model behavior, so validate source, intent, destinations, and resulting state.
4. Revoke the exposed token immediately; create a least-privilege replacement and update its secret store; restart workloads that must reload it; inspect Git history, workflow runs, issue/PR activity, and any agent-written state from the exposure window; remove the credential from history using the team's approved history-rewrite procedure if needed; then verify the new token's scope and that old credentials fail. Removing a line from the current file alone is not containment.

## Quiz Answers

1. Shared state persists across sessions and can be read by agents that never saw the original untrusted issue. It can launder attacker-supplied instructions into a trusted-looking project file.
2. No. `gh auth switch` selects the local CLI identity for a GitHub host. An Actions job uses its configured token and permissions.
3. Azure workload identity authenticates to Azure resources. A GitHub App installation token authenticates to GitHub APIs and is scoped to an App installation. Azure identity may retrieve a GitHub token from Key Vault but does not replace it.
4. It checks selected diff patterns and, by design, exits zero even when it reports findings. It cannot prove a change safe or detect every credential, vulnerability, or prompt attack.
5. Examples include Copilot plugin requirements, package install hints, upstream commands, MCP server hints, and provider contracts. These are descriptive metadata in the plugin lifecycle, not authority to run installs or start servers.
6. Revoke or rotate the credential immediately, then inspect history and logs and audit activity performed with it. A later deletion does not invalidate a credential already disclosed or erase previous commits.
