# Chapter 1 Solutions

## Exercise Solutions

1. In a current v1.1.0 initialized project, `.mcp.json` at the repository root is the authoritative generated location for `mcpServers.squad_state`. Older `.copilot/mcp-config.json` files may remain for unrelated services, but init removes the stale Squad-owned entry there. Preserve the root file’s sibling keys and inspect the exact launcher generated by the installed version.
2. A review checklist should verify the server’s maintainer and source, exact launch command and version, transport/client compatibility, required environment variables and secret injection, whether the config is committed, least-privilege tool exposure, expected side effects, error logging, update policy, and a rollback path. The reviewer should test it with non-production credentials and make sure no secret appears in Git history or logs.
3. `--yolo` suppresses tool-consent prompts, but the Copilot CLI’s workspace trust gate controls whether it loads workspace `.mcp.json` in non-interactive mode. Squad’s managed subprocess path uses `--additional-mcp-config @<absolute-path>` to explicitly name the configuration; `--yolo` addresses the separate risk of a blocked consent prompt.
4. Test only in a disposable Git repository. Record the `squad` version and `squad init --help` output; run init with `--mcp-frontmatter`; inspect `.github/agents/squad.agent.md`, `.mcp.json`, and `.copilot/mcp-config.json`; compare to normal init; then verify the tools in the target client. The inspected v1.1.0 parser recognizes the option, but installed help omits it and the CLI subsequently ensures `.mcp.json`, so do not assume frontmatter mode yields a single-file bundle.

## Quiz Answers

1. The MCP host reads server configuration, starts or connects to servers, exposes their advertised tools to the model, and mediates calls and responses.
2. No. It contributes tools to the Copilot host. A Squad agent is an agent identity with a charter and work context; an MCP server is a tool provider.
3. The repository-root `.mcp.json` contains the CLI-generated `squad_state` entry.
4. `--additional-mcp-config @<path>` explicitly loads the project file; `--yolo` suppresses per-tool consent prompts in the non-interactive flow. They solve different problems and both have security implications.
5. The host can execute the configured program with the provided environment. That grants code execution and access to any credentials or permissions inherited by the process.
6. Confirm that the target harness consumes frontmatter MCP configuration, that its schema matches the emitted `mcpServers` shape, and that its runtime correctly resolves the command, arguments, credentials, and tools.
7. Check server startup and protocol compatibility, credentials/service authorization, tool arguments, active backend/repository resolution, and whether the operation is allowed. Tool registration does not guarantee successful service calls.
