# Chapter 18 Solutions

## Exercise Solutions

1. **Map the planes.** The client parses the user's host-specific request and dispatches the coordinator through that host's tools. The coordinator and broker/control contract establish the conversation, sequence its events, apply policy, and persist the shared state. The execution plane runs the task through a host subagent or registered harness, invokes tools, and returns results. Switching from Copilot to Claude Code may change dispatch syntax and projected files; it should not change the specialist's shared charter, the agreed team policy, or the meaning and order of durable conversation events.

2. **Plan a two-host projection.** For a full Claude Code projection, expect `.claude/agents/squad.md` (the coordinator), one `.claude/agents/<member>.md` subagent per team member including the built-ins, Squad's skills under `.claude/skills/` (among them the `squad-coordinator-*` mode skills), `.claude/settings.json` with the scoped permission allowlist and its record in `.claude/.squad-permissions.json`, the managed `CLAUDE.md` block, `.mcp.json`, and a managed `.gitignore` entry for `.claude/worktrees/`. In plugin mode the coordinator, skills and hooks come from the plugin instead, and the repository keeps the member subagents, the `CLAUDE.md` block and two `.claude/settings.json` keys. Either way, the same `.squad/team.md`, charter directories, decisions, and routing remain authoritative. The member subagents are generated from the charters and refreshed by `squad cast` or `squad client sync`; they do not define a second Claude-only roster. Choose the exact client ID explicitly and review additions to shared files.

3. **Write a migration checklist.** Replace client imports with `@bradygaster/squad-sdk/client`; keep the old `clients` alias only during a transition. Import backend interfaces from `@bradygaster/squad-sdk/backend`, not the root package. For state MCP, pass `--experimental-backend` or set `SQUAD_EXPERIMENTAL_BACKEND=1`; do not rely on `SQUAD_BACKEND_URL` to enable it. Instantiate `DurableHttpSquadBackend` with explicit `baseUrl` and optional token, using HTTPS except for loopback. Write `team.md`, `routing.md`, `config.json`, and charters through the workspace/appropriate CLI rather than `squad_state_write`; keep `.squad/casting/` out of hand-edit workflows. Verify with a type-check/import test, inspect the MCP server configuration, test URL validation, and confirm static files are edited in version control.

4. **Audit the safeguards.** Example answers: (a) *Epochs are client-asserted.* Failure mode: a buggy or hostile same-user caller presents a larger epoch and takes over a run. Cover it by running the backend behind a service boundary that authenticates callers, not on a shared account. (b) *Squad does not validate your own MCP `command` and `args`.* Failure mode: a pull request adds a launch command that runs something unexpected when a teammate opens the repo in their host. Cover it with code review and branch protection on `.mcp.json` and the other hosts' config files. (c) *The dashboard shows transcripts to anyone who can reach the port.* Failure mode: another local user, or a forwarded port, exposes session content. Cover it by not forwarding the port and stopping the dashboard (`squad dashboard stop`) on shared machines. Other good picks: unsigned cursors, the missing broker-computed approval digests, and G8's unknown-event gap. Any three earn credit when the answer separates a correctness safeguard from a security boundary.

5. **Resolve upstream order.** The local project's value wins first. When upstream values conflict with each other, `org` wins over `team`, which wins over `legacy`, because earlier entries win. The old later-wins documentation would have produced `legacy` as the winner. To migrate safely, run `squad upstream sync`, inspect which rules conflict, then use upstream remove/add to reorder entries so the intended source appears first; preserve the repository's local rule if it should override all inherited choices.

6. **Take Tasktrack's inventory.** `squad --version` prints `2.0.0`. For a Copilot-only Tasktrack, `squad client list` reports that `clients[]` is empty and that `copilot` is projected with 2 of 2 files (`.github/agents/squad.agent.md` and `.mcp.json`). In `squad health --json`, `resolvedTeamRoot` is the Tasktrack folder and `resolvedSquadDir` is its `.squad` folder (macOS may show a `/private/...` spelling). The doctor line reads "portable squad_state launch: 1 committed launch command(s) are portable" with a check mark. After `squad client add claude`, `clients[]` holds `claude` and `squad client list` lists Claude Code as projected and no longer lists Copilot, because a non-empty `clients[]` that does not name `copilot` leaves it out of the list (its files remain and it still works); the new files are the Claude coordinator, one member subagent per roster member, the skills, `.claude/settings.json` and `.claude/.squad-permissions.json`, the `CLAUDE.md` block, and a `.gitignore` entry for `.claude/worktrees/`. The Copilot files stay in place.

## Quiz Answers

1. One repository-owned `.squad/` team can be used through multiple host-native integrations without keeping separate, drifting team definitions. Host files are projections, while the roster and charters stay shared.
2. **Client plane:** host configuration, UI/event adaptation, and dispatch. **Control/broker plane:** conversation identity, ordering, approvals, capabilities, cancellation, and durable history. **Execution plane:** workers, tools, checkpoints, retries, and task execution.
3. Intersection ensures a capability is effective only if the host offers it, the backend supports it, and policy permits it. A union would incorrectly claim a feature when any necessary layer lacks it or disallows it.
4. The bridge exposes the backend tools only when started with `--experimental-backend` or `SQUAD_EXPERIMENTAL_BACKEND=1`; `SQUAD_BACKEND_URL` by itself does not enable them. They execute a turn only when a harness is registered: the bridge registers `ClaudeAgentSdkHarness` when the optional `@anthropic-ai/claude-agent-sdk` peer is installed, and `CopilotSdkHarness` only when `SQUAD_BACKEND_HARNESSES` lists it (`none` turns both off). With no harness, health and negotiate report `executionAvailable: false` and `squad_backend_send_message` refuses. All of it is experimental in v2.0.0, and there is no bundled remote server.
5. Squad no longer finds or falls back to a profile-level personal/global team; resolution is project-local, walking from the current directory through parents and respecting repository boundaries. Run `squad init` in the project or use `--team-root <path>` where supported to select an explicit team root.
6. Local project configuration wins; then earlier upstream entries win over later entries. Run `squad upstream sync` after upgrading and reorder configured sources if you relied on the prior later-wins behavior.
7. Run `squad roster add rai` (or preview it with `--dry-run`). Upgrades preserve `team.md`; the explicit command inserts the optional built-in row and records a verified backup and provenance so later removal can target only its own change.
8. No. ADR-001 describes epochs as cooperative, client-asserted fencing values that reject stale writers, but any caller able to present a larger value can take over. They have no broker-issued holder identity or expiry and are not an authentication/authorization boundary.
