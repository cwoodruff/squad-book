# Chapter 22 Solutions

## Exercise Solutions

1. A prerelease CLI follows `@insider` by default, while a stable CLI follows `@latest`. Adding `--insider` forces the `insider` tag explicitly. `--force` bypasses the self-upgrade's older-version refusal; it does not make an older CLI safe to run against a 2.0 project.

2. The real upgrade should not commit a partial repair. It should report the failed candidates and leave the casting registry/history pair unchanged, while preserving or creating the content-addressed archive only as part of a successful transactional repair. The developer should correct only the source facts that can be proven, repeat the dry run, and then apply. A partial registry could conceal lost or misidentified agents and would make historical identity unreliable.

3. Start with a clean branch and initialize a project-local squad. Copy only the API charter and useful API history into that project's `.squad/agents/` tree, reconcile the charter identity and folder ID against `team.md` and casting, and bring over the shared decision only after reviewing whether it applies. Do not copy credentials, profile caches, unrelated project history, or global configuration wholesale. Repeat the review independently for the second project.

4. Put `org-security` before `team-defaults` so the higher-priority source is earlier. Run `squad upstream sync` to refresh the local snapshots; a session reads those local snapshots but does not fetch remote sources on startup. Then inspect `squad doctor` and `squad status`.

5. No. The CLI processes `--migrate-directory` before the project dry-run path, so the legacy rename can happen before the preview. Use `squad upgrade --dry-run` by itself first; plan and perform the directory migration as a separate, backed-up step.

6. No. The projection creates or updates host-native coordinator and MCP configuration files and records the selected host in `clients[]`. It does not install Claude Code, sign in, or provide a license. Verify the host's own installation, authentication, and access separately; use Copilot for the rest of the lab if no other host is available.

## Quiz Answers

1. `latest` remains on Squad 1.1.0.
2. No. Self-upgrade installs only the CLI package. Run `squad upgrade` separately in each project.
3. The registry must be empty and have no meaningful prior cast history; every specialist roster row must resolve to one existing charter folder, and the team must state a universe. If any fact is missing or ambiguous, the backfill fails closed.
4. It lists records that could not be normalized and their reasons. It does not mean a partial registry was committed; the repair refuses the whole operation.
5. `squad health` performs stronger semantic routing-reference validation. `squad doctor` checks routing-file presence and casting-pair consistency.
6. Earlier entries win.
7. No. `uninstallClients()` removes generated client projections only; it is not a package downgrade or project rollback.
8. Restore the project files and state to the 1.1.0 baseline first, then install the 1.1.0 CLI and validate the restored project.
