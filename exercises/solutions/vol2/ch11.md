# Chapter 11 Solutions

## Exercise Solutions

1. Session creation belongs to the Squad SDK client/session adapter and its host-specific spawn mechanism. Listing GitHub issues belongs to a work-platform adapter (or CLI command using one). Displaying a shell prompt belongs to the CLI. Parsing direct-agent syntax belongs to a shell router such as `packages/squad-cli/src/cli/shell/router.ts`. Exact composition varies by execution path, so verify the caller rather than assigning every task to one package.
2. In the prompt path, the host applies `.github/agents/squad.agent.md`, interprets its routing policy, and dispatches through the available host tool. In the SDK path, application code calls `SquadCoordinator.handleMessage()`, which checks its direct responder, invokes the compiled router, determines a spawn strategy, and optionally calls injected fan-out dependencies. The paths may choose similar specialists but do not share one universal coordinator implementation.
3. Example: the SDK adapter exposes a stable `SquadSession` contract and maps upstream Copilot behavior to it. This is a package/API boundary implemented in TypeScript. By contrast, the rule that a coordinator must dispatch domain work to a specialist is a host instruction. A matching session event or adapter implementation demonstrates the runtime mechanism; a prompt rule alone establishes policy, not enforcement in every host.
4. “The coordinator” can refer to the full Copilot agent prompt, the CLI shell's prompt/parser protocol, or one of multiple SDK coordinator implementations. Before filing, record the client surface/version, the active team root and state backend, the request, the selected route/mode, and whether a host spawn tool was available.

## Quiz Answers

1. The CLI package, `@bradygaster/squad-cli`, supplies the `squad` executable. The SDK is a reusable library.
2. It shields Squad code from direct dependence on upstream Copilot session/client types and translates options/events as required.
3. Normalized work-item and pull-request operations, including listing/getting/creating work items, labels/tags, assignments, comments, branches, PR creation, and merging.
4. No. The function is exported by the SDK, but the inspected `SquadCoordinator.handleMessage()` path does not invoke it. A caller must wire it in for it to govern that path.
5. The v1.1.0 checkout contains no `docs/specification/adr-001*` documents and no verifiable explicit Squad 2.0 design statement. It does not establish a future design contract.
6. The SDK root entry point is designed as a side-effect-free public API; the CLI executable and its interactive shell live in the separate CLI package.
