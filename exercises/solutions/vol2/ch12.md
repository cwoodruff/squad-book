# Chapter 12 Solutions

## Exercise Solutions

1. A reasonable sequence is state/team-root resolution, Init-versus-Team check, routing/scope control, skill-aware routing if relevant, response-mode selection, client compatibility and state-backend checks, spawn, then after-agent handoff. A skill scan need not apply to a factual Direct answer; likewise a ceremony section is irrelevant unless its trigger matches.
2. An agent must not rewrite a prior decision to change its meaning. The coordinator accepts a correction as a new append-only entry that references the prior decision. For an external/non-local state backend, use the configured runtime state bridge; do not write directly to `.squad/decisions.md` or its inbox. If the bridge is not reachable, halt state mutation.
3. Propose a project-specific roster, including role responsibilities and names, then ask for confirmation with the entire proposal included in the question. Before confirmation, do not create the `.squad/` scaffold, team/routing files, casting registry/history, or `.gitattributes` merge-driver changes. Confirmation begins Phase 2.
4. The extra Tester and Reviewer are unsolicited follow-up agents unless required by the user, governance, or a declared dependency. The reminder repeats context the agent already has. The compliant alternative is one accountable Backend owner with an explicit scope; ask the user or follow a required review gate if more work is needed, and avoid intervention while the agent runs.
5. Both paths prepare a bounded task and dispatch work to an agent, then collect a result. The prompt path applies host-specific governance, routing, mode choice, scope, and user-facing restraint. `spawnParallel()` compiles charters, resolves session settings, prepares/sanitizes prompts, creates sessions and records results/events; it does not itself decide all prompt policy or approve accepted decisions.
