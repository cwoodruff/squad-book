# Chapter 5 Solutions

## Exercise Solutions

1. **Client acceptance test.** Record client and extension versions, workspace trust, coordinator discovery, and the tools each host exposes. For CLI and VS Code, test a read-only route, then a bounded delegated task if the host offers one; capture how the result is collected. In a throwaway branch, test a harmless write, inspect the diff and approval prompt, and invoke one configured MCP tool. Hide or disable delegation and verify that the coordinator handles a smaller task inline. Mark JetBrains or GitHub.com unknown unless independently tested.
2. **Portable workflow.** A suitable instruction is: “Classify the request, identify independent work, and delegate only through tools available in this host. If no supported delegation tool is available, handle a smaller unit inline and state that no child agent was started. Verify results before integrating them.” This describes intent without requiring a specific client API.
3. **Programmatic API boundaries.** `SquadClient` provides programmatic Copilot sessions; `SquadClientWithPool` adds the session pool and event bus. The pool bounds concurrency and tracks lifecycle, while the event bus exposes session and routing events. These SDK calls connect to the Copilot SDK server and do not establish that an IDE exposes the same subagent tools.
4. **Shared-checkout policy.** Give each client a separate branch or worktree, require status/diff inspection before committing, and integrate through a reviewable merge or pull request. If clients must share one checkout, serialize writes and require the second client to inspect the first client's changes before editing.

## Quiz Answers

1. Each client exposes different tools, permissions, model controls, and result-handling behavior; repository instructions do not standardize the host runtime.
2. The CLI reference describes background `task` calls with later collection through `read_agent`; the VS Code flow returns results with the subagent call and does not use CLI-style polling.
3. Handle a smaller task inline with the coordinator, and be transparent that no child agent was started.
4. `SquadClientWithPool`, which combines the Copilot-backed `SquadClient` with a `SessionPool` and `EventBus`.
5. No. Shared repository files provide common instructions, not locking or conflict prevention. Use separate branches/worktrees or serialize writes.
6. Part IV, especially Chapters 19–20, covers Squad 2.0's multi-client projections.
