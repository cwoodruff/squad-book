# Chapter 13 Solutions

## Exercise Solutions

1. **Trace the identity layers.** `git config user.name` (and email) tells Git which author/committer identity it will record by default; it does not identify a Squad agent. A registry object key such as `runtime-engineer` is the stable logical identity, while `display_name` is a mutable presentation label. A work-binding row relates a task and issue to that stable ID at a particular registry revision. If no binding exists, the assignment is unknown; do not infer it from an issue assignee or commit author.

2. **Plan a rename safely.** Keep the stable ID `runtime-engineer`, preserve its creation timestamp and role, and update `display_name`, the equal compatibility `persistent_name`, `universe` if appropriate, and `updated_at`. Keep historical bindings unchanged. Creating a second ID risks splitting the same logical agent's history and violates the rule that a recast must supply the existing stable ID explicitly.

3. **Diagnose an incomplete registry.** The dashboard may render valid individual profile records if it clearly reports partial/incomplete identity data. It must not treat the result as a complete authoritative registry or validate work bindings against it. Binding resolution requires a complete registry, and invalid rows are not silently repaired or inferred.

4. **Classify canary observations.** `(present, present)` means the marker-bearing payload appears fully loaded in an independently known coordinator session. `(present, absent)` means apparent truncation; halt. `(absent, absent)` is ambiguous and requires independent runtime evidence; do not automatically skip or continue.

5. **Design a safe attribution note.** Example: “Task #45 implementation was assigned to Squad agent `runtime-engineer` (display name Kepler, registry revision 4); Jane Developer reviewed and committed the change.” The exact names and task reference should reflect the real record. The note keeps logical assignment separate from Git author/committer and uses no invented email. A repository may define a co-author convention, but it must be followed explicitly with an authorized identity.
