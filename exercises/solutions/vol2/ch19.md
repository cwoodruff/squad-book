# Chapter 19 Solutions

## Exercise Solutions

1. **Map the projection.** Copilot uses `.github/agents/squad.agent.md` as a managed coordinator and `.mcp.json` as a JSON config with `mcpServers.squad_state`. Claude creates managed `.claude/agents/squad.md`, merges the same `.mcp.json` entry, adds a managed block to `CLAUDE.md`, and adds `.claude/worktrees/` under `# squad:claude` in `.gitignore`. Codex creates managed `.codex/agents/squad.toml`, adds a Codex-ID marker block to `AGENTS.md`, and upserts `[mcp_servers.squad_state]` in `.codex/config.toml`. Copilot and Claude share `.mcp.json`. Uninstalling only Claude while keeping Copilot should remove Claude's managed agent file and its pointer/ignore additions, while `.mcp.json` remains for Copilot.

2. **Portable client configuration.** Known IDs are trimmed, lowercased, de-duplicated, and returned in canonical order. A token-like string or filesystem path is classified as sensitive and redacted in diagnostics; it is not accepted as a client. A safe unknown slug is also not a host this CLI can project, but the CLI can preserve a safe, slug-shaped unknown value already in `clients[]` so that an older version does not erase a future host ID. `assertPortableClients()` rejects invalid values, unknown IDs, and duplicates instead of preserving them.

3. **MCP approval diagnosis.** Use `claude --agent squad --mcp-config .mcp.json`; for headless use, pass `--mcp-config .mcp.json` with `claude -p`. Approve the project server once and verify it with `claude mcp list`. Squad deliberately does not enable all project MCP servers in `.claude/settings.json`; project approval remains an explicit host trust choice. For Cursor, run `cursor-agent mcp enable squad_state` once.

4. **Static or mutable?** Add an API specialist with `squad cast --name ... --role "..."` and inspect the static `.squad/team.md` / `.squad/agents/<name>/charter.md` results. Update the static `.squad/routing.md` as a normal file edit. Record a durable decision with `squad_decide`. Append an agent learning through the appropriate `squad_state_*` runtime tool (for example, state append). Add a host projection with `squad init --client ...`, `squad upgrade --client ...`, or `squad client add ...`; the selected host IDs are saved in `.squad/config.json`.

5. **Removal plan.** Call SDK `uninstallClients(['claude'], ctx, ['copilot','codex'])`, using the actual project root and MCP launch context. The `keep` list prevents removal of `.mcp.json`, which Copilot still uses. Remove `claude` from `.squad/config.json`'s `clients` array so a later upgrade does not re-project it. Compare Claude-owned paths such as `.claude/agents/squad.md`, `CLAUDE.md`, and `.gitignore` against the pre-projection baseline. Check `.mcp.json` separately; it should continue to contain Copilot's entry.

## Quiz Answers

1. Seven host coordinators can point at one `.squad/` team; it does not create seven rosters.
2. It adds Claude and Codex to the requested set, refreshes them, and also refreshes any configured host such as Copilot.
3. `squad client list` (also `ls`) and `squad client add <list> [--dry-run]` are defined. There is no `squad client remove` subcommand in this preview.
4. Claude needs the project `.mcp.json` explicitly passed as `--mcp-config .mcp.json`; a headless `claude -p` invocation without it may lack the state tools.
5. `cursor-agent mcp enable squad_state`.
6. A full path in Codex home configuration; the guide warns against an 8.3-style short path.
7. Google Antigravity. Quota is per model, and `--model` selects an alternate.
8. Record runtime decisions with `squad_decide`; edit the static `.squad/routing.md` as a workspace file (or use the relevant Squad CLI workflow).
