# Chapter 19 Solutions

## Exercise Solutions

1. **Map the projection.** Copilot uses `.github/agents/squad.agent.md` as a managed coordinator and `.mcp.json` as a JSON config with `mcpServers.squad_state`. Claude (full projection) creates managed `.claude/agents/squad.md`, one managed member subagent per roster member under `.claude/agents/`, and managed skills under `.claude/skills/`; merges its permission rules into the user-owned `.claude/settings.json` (recorded in `.claude/.squad-permissions.json`); merges the same `.mcp.json` entry; adds a managed block to `CLAUDE.md`, and adds `.claude/worktrees/` under `# squad:claude` in `.gitignore`. Codex creates managed `.codex/agents/squad.toml`, adds a Codex-ID marker block to `AGENTS.md`, and upserts `[mcp_servers.squad_state]` in `.codex/config.toml`. Copilot and Claude share `.mcp.json`. Uninstalling only Claude while keeping Copilot should remove Claude's managed coordinator, member and skill files, Squad's rules in `.claude/settings.json`, and its pointer/ignore additions, while `.mcp.json` remains for Copilot.

2. **Portable client configuration.** Known IDs are trimmed, lowercased, de-duplicated, and returned in canonical order. A token-like string or filesystem path is classified as sensitive and redacted in diagnostics; it is not accepted as a client. A safe unknown slug is also not a host this CLI can project, but the CLI can preserve a safe, slug-shaped unknown value already in `clients[]` so that an older version does not erase a future host ID. `assertPortableClients()` rejects invalid values, unknown IDs, and duplicates instead of preserving them.

3. **MCP approval diagnosis.** With the full projection, use `claude --agent squad --mcp-config .mcp.json`; for headless use, pass `--mcp-config .mcp.json` with `claude -p`. Approve the project server once and verify it with `claude mcp list`. Squad deliberately does not enable all project MCP servers in `.claude/settings.json`; project approval remains an explicit host trust choice. If the team uses plugin mode instead, the plugin serves `squad_state` with no approval and no `--mcp-config`, so `claude -p --agent squad:squad` is enough. For Cursor, run `cursor-agent mcp enable squad_state` once.

4. **Static or mutable?** Add an API specialist with `squad cast --name ... --role "..."` and inspect the static `.squad/team.md` / `.squad/agents/<name>/charter.md` results. Update the static `.squad/routing.md` as a normal file edit. Record a durable decision with `squad_decide`. Append an agent learning through the appropriate `squad_state_*` runtime tool (for example, state append). Add a host projection with `squad init --client ...`, `squad upgrade --client ...`, or `squad client add ...`; the selected host IDs are saved in `.squad/config.json`. After the routing change, run `squad client sync` so Claude Code's member subagent descriptions match.

5. **Removal plan.** If Claude was added in its own recent commit, the Git route is simplest: restore `.gitignore` (and any pre-existing `CLAUDE.md`) from the baseline and remove `.claude/` and a Squad-created `CLAUDE.md`. Otherwise call SDK `uninstallClients(['claude'], ctx, ['copilot','codex'])`, using the actual project root and MCP launch context. The `keep` list prevents removal of `.mcp.json`, which Copilot still uses. Remove `claude` from `.squad/config.json`'s `clients` array so a later upgrade does not re-project it. Compare Claude-owned paths (`.claude/`, `CLAUDE.md`, and `.gitignore`) against the pre-projection baseline. Check `.mcp.json` separately; it should continue to contain Copilot's entry.

6. **Plugin or full projection?** The security review requirement points to the full projection: every Squad file that runs (the coordinator `.claude/agents/squad.md`, the member subagents, the skills under `.claude/skills/`, the `.mcp.json` entry, `.claude/settings.json` rules and `.claude/.squad-permissions.json`, the `CLAUDE.md` block and the `.gitignore` entry) is in the repository and in code review. Plugin mode would put only the member subagents, the `CLAUDE.md` block, the `.claude/settings.json` keys (`agent`, `disabledMcpjsonServers`, the allowlist and `enabledPlugins` from the project-scope install) and `.claude/.squad-plugin-settings.json` in the repository, with the coordinator, skills, hooks and MCP server coming from the plugin; that is less to maintain, so it is a fair answer if the review can cover the plugin's published source instead. Either way the Copilot users are unaffected. On first launch in a fresh clone, each Claude Code user runs `claude` interactively and accepts the folder trust prompt, so the allowlist applies; with the full projection they also approve the project `squad_state` server once (or pass `--mcp-config .mcp.json`), and with plugin mode they install the plugin when Claude Code offers it.

## Quiz Answers

1. Seven host coordinators can point at one `.squad/` team; it does not create seven rosters.
2. It adds Claude and Codex to the requested set, refreshes them, and also refreshes any configured host such as Copilot.
3. `squad client list` (also `ls`) and `squad client add <list> [--dry-run]` and `squad client sync [--dry-run]` are defined. There is no `squad client remove` subcommand in 2.0.0.
4. With the full projection, Claude needs the project `.mcp.json` explicitly passed as `--mcp-config .mcp.json` (or a prior approval for the project); a headless `claude -p` invocation without it may lack the state tools. In plugin mode the plugin serves `squad_state`, so no approval or `--mcp-config` is needed, and `.claude/settings.json` disables the `.mcp.json` copy through `disabledMcpjsonServers`.
5. `cursor-agent mcp enable squad_state`.
6. A full path in Codex home configuration; the guide warns against an 8.3-style short path.
7. The folder is not trusted yet. Claude Code applies project allow rules only after you accept the trust prompt on the first interactive `claude` run there, and it ignores them in headless runs in an untrusted folder. (Also check that `claudePermissions` is not `"off"`.)
8. Record runtime decisions with `squad_decide`; edit the static `.squad/routing.md` as a workspace file (or use the relevant Squad CLI workflow).
