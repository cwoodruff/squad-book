# Chapter 10 Solutions

## Exercise Solutions

1. Check in order: (1) pod/process startup and logs, (2) `squad watch`/worker execution path, (3) qualifying GitHub issue and label, (4) GitHub token presence/scope/account access, (5) state backend and volume access, and (6) KEDA/scaler status and reachability. Inspect routing rules after verifying the upstream boundaries. Preserve logs/state before restarting or changing multiple settings.
2. A complete answer shows: a clean baseline commit/tag; a disposable branch; an identified tracked file restored from the baseline; a diff confirming the intended content; successful `npm test`; a healthy Tasktrack `/health` response; and a note distinguishing the API's in-memory task data from Git-backed Squad state. It should identify external state that was not covered by Git and propose a separate restore test if applicable.
3. Collect OS/editor version and build, extension versions, whether the CLI or child processes remain alive, terminal logs, workspace Git status, memory/CPU observations, open terminals, and a minimal reproduction. Do not conclude causation until evidence distinguishes editor failure from process failure.
4. Example: “Review Tasktrack at branch `feature/pagination`, commit `<sha>`. Inspect only `api/src/` and `api/test/`; compare route behavior with tests; do not modify files. Report specific missing boundary tests with file/line evidence and identify assumptions. A maintainer will review all findings before changes.” Ensure the remote workflow actually checks out that branch/commit.

## Quiz Answers

1. No. Git can restore only content represented in the index, commits, or another backup.
2. A running pod proves that Kubernetes started a process. A ready worker also needs working authentication, routing, state access, and any required scaler/queue path; v1.1.0 does not provide a built-in HTTP readiness endpoint for all of that.
3. The runtime has no built-in `/healthz` or `/readyz` HTTP endpoint that confirms GitHub connectivity/readiness.
4. No. A longer grace period gives a process more time to exit but does not guarantee checkpointing; the documented runtime does not checkpoint in-flight tasks before shutdown.
5. Streaming usage history: 1,000 FIFO events. Telemetry collector queue: 500 FIFO events.
6. Remote paths can use the default branch and may not see a feature branch or local state. Naming and verifying the target revision prevents stale-context QA.
7. It can destroy durable team knowledge and diagnostic evidence without distinguishing state corruption from code/runtime problems.
