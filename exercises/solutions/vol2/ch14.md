# Chapter 14 Solutions

## Exercise Solutions

1. **Entrypoint audit:** A sample audit might list `resolveSquad` from the root, `SquadClientWithPool` from `/client`, `SquadCoordinator` from `/coordinator`, `ToolRegistry` from `/tools`, and `HookPipeline` from `/hooks`. If an application imports `packages/squad-sdk/src/client/session-pool.ts`, replace it with a public import such as `@bradygaster/squad-sdk/client`. Check each symbol against the v1.1.0 `exports` map; the root does not re-export every class from every subpath.

2. **Config contract comparison:** An SDK-first builder config has `team`, `agents`, and `routing.rules` entries such as `{ pattern: 'api', agents: ['backend'] }`, plus optional `defaults`, `hooks`, `skills`, and other builder sections. The runtime loader config instead includes `models.defaultModel`, `models.defaultTier`, `models.fallbackChains`, and `routing.rules` entries with `workType` and `agents`; it has no `team` or `agents` field. They are separate source-level contracts, so neither a type cast nor a rename of one field is a safe conversion. Write and test a mapper that translates the fields the runtime actually needs, or use `squad build` and inspect the generated markdown.

3. **Lifecycle test:** Inject a fake session creator that rejects after charter compilation and model selection. Assert that the call reports an error (or partial spawn status) rather than pretending the route succeeded; no active handle is left registered; any created client/session resources are closed; event listeners are removed; and the caller can still shut down the client safely. A second test should cover a successful spawn followed by `destroyAgent()` and assert that the handle reaches its destroyed state and metrics/events are emitted as expected.

4. **Sample selection:** For a project that needs a guarded tool policy, `hook-governance` is the closest example. Reuse its construction and registration of hooks, but do not assume configuration alone activates a policy or that its example rules are a security boundary in your host. Add tests for allowed and blocked operations, policy ordering, and failures in hook handlers. For live multi-agent chat, `streaming-chat` is a better fit; test route selection, session cleanup, and listener removal separately.

5. **Tasktrack config inspector:** Add a loop over `config.agents` to print `name` and `role`, print `config.routing?.fallback ?? 'unspecified'`, and compute whether some routing rule has at least two agents and mentions `contract` or `cross-layer` in its pattern. Keep import and output logic free of write APIs. Put the formatting in a pure function and test it with a small config whose `routing` is absent, confirming it prints the team and an empty or “none” routing section without throwing. For a testable Node setup, use the project's supported TypeScript runner or factor the pure formatter into a JavaScript module that `node:test` can import.

## Quiz Answers

1. `defineConfig()` describes a public config schema with `team`, `agents`, `routing.pattern`, and model defaults, while SDK-first builders define a composable `SquadSDKConfig` that `squad build` compiles into markdown files.
2. It returns `null` when it cannot find `.squad/`.
3. `SquadClientWithPool` is exported from `@bradygaster/squad-sdk/client`; `SquadCoordinator` is exported from `@bradygaster/squad-sdk/coordinator`.
4. The route tool needs fan-out dependencies (including a session-spawn capability) to create the requested work. A registry without them cannot spawn sessions.
5. It loads a `SquadSDKConfig`, plans and generates files such as `.squad/team.md`, `.squad/routing.md`, and agent charters, with dry-run and drift-check modes available.
6. No. A typed rule is configuration data. Dispatch requires a compatible runtime coordinator and spawn dependencies; authentication and session creation are separate concerns.
7. The source `ConfigLoadResult` contains `config`, optional `source`, and `isDefault`; the runtime `SquadConfig` does not define `team`, and the loader does not return `errors` or `warnings`. The docs and current source disagree on these examples.
8. Remove event listeners/detach the streaming pipeline and shut down or disconnect the client/session pool. Also destroy owned agent handles where the application manages them.
