# Chapter 14 Solutions

## Exercise Solutions

1. Put `cleanup` inside `.squad/config.json` under `watch`, with `everyNRounds: 4` and `maxAgeDays: 45`. Enable it with `squad watch --cleanup` (or by the `watch.cleanup` object in config). It is not enabled just by setting `--execute`.
2. The upgrade warns if a manifest-listed built-in skill differs, then overwrites it; the warning is not a backup. Commit or copy the customization independently, or move it into a user-owned/custom skill location before upgrading.
3. `--self` installs the global CLI package. The plain project command refreshes managed files and runs repository migrations. Run `squad upgrade` at the Tasktrack root to refresh that repo.
4. Cleanup decides age from a `YYYY-MM-DD` prefix in the filename, not the file's modification time; `watch-latest.md` has no qualifying date prefix. A dated inbox Markdown file older than seven days is reported as stale but is not merged or deleted by cleanup.
5. The migration refuses when `.squad/` already exists, rather than renaming `.ai-team/` over it. Back up the project and resolve which directory is authoritative before retrying.

## Quiz Answers

1. No. Cleanup is opt-in as a watch capability.
2. No. The implementation deletes matching old entries rather than archiving them.
3. The date prefix in the filename, compared to `maxAgeDays`; the filename must begin with `YYYY-MM-DD`.
4. No. The v1.1.0 self-upgrade path installs the CLI and returns; run the project upgrade separately.
5. Manifest-listed Squad-owned templates are refreshed. Team state such as histories and decisions is preserved.
6. No. The CLI warns and overwrites; keep an independent backup.
7. It refuses if `.ai-team/` does not exist or if `.squad/` already exists.
8. The dispatcher performs migration and self-install actions before the project dry-run logic. Those options are mutating and are not simulated by `--dry-run`.
