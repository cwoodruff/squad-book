# Chapter 17 Solutions

## Exercise Solutions

1. **Tighten discovery.** Good triggers might be `api`, `endpoint`, `task status`, `PATCH`, and `node:http`, depending on the exact simple parser behavior and task phrasing. Test realistic prompts rather than maximizing trigger count. Since matching uses case-insensitive substring search, a short trigger such as `api` may match inside a longer unrelated word; broad terms can surface the skill when it is not relevant.

2. **Author a skill.** Example:

   ```markdown
   ---
   name: Tasktrack Test Conventions
   domain: api-testing
   triggers: [test, node:test, regression]
   roles: [tester, backend]
   confidence: low
   ---

   ## Pattern
   Add regression tests with Node's built-in `node:test` runner. Verify route behavior through `api/test/app.test.ts` and run `npm test` from the Tasktrack root. Check the current source before assuming a response code.
   ```

   The frontmatter stays in the parser’s supported subset, and the body gives both a procedure and a source of truth.

3. **Score a match.** The task “Update the status endpoint” hits `status` and `endpoint`, producing 0.7 trigger points because two hits exceed the 0.7 trigger cap. The role `backend` matches, adding 0.3. The total is 1.0. Note that the code checks substrings, not whole words.

4. **Audit the release surface.** Examples: current Squad templates use `.github/skills` while the docs and SDK local source focus on `.copilot/skills`; the CLI uses lowercase `skill.md` while SDK loading expects `SKILL.md`; and docs describe `MarketplaceBrowser.install()` as an installer while the code only fetches a package buffer and reports size. Another discrepancy is documentation for `AgentCache` and semver helpers that are not in the v1.1.0 marketplace module. For code targeting the release, use the tagged source files and actual package exports; use docs as background and flag a mismatch rather than inventing the missing API.

5. **Security review.** Markdown scanning cannot examine the runtime behavior of imported JavaScript handlers, and a textual pattern scanner can miss obfuscation or behavior that does not match its rules. Review the script source and its dependencies, run it in a constrained test environment, restrict filesystem/network access where possible, minimize the tools and configuration it can use, and never embed credentials in a committed skill. A path-containment check prevents path escape during resolution but does not sandbox code after import.

## Quiz Answers

1. `name`, `domain`, `triggers`, and `roles` (returned as `agentRoles` on `SkillDefinition`).
2. Each trigger substring match adds 0.5 points, with the trigger contribution capped at 0.7. A matching role adds 0.3; total score is capped at 1.0.
3. No. Confidence is frontmatter metadata and does not affect the registry’s score or ordering.
4. The APM-oriented CLI reads lowercase `skill.md`. The SDK loader reads uppercase `SKILL.md`.
5. No. The v1.1.0 browser obtains package bytes through its fetcher and returns an install result; it does not unpack or write them to the target directory.
6. The marketplace security module validates remote agent definitions, including charter injection patterns, requested tools, possible PII, permission language, source, and charter presence. It is not a scanner for arbitrary skill Markdown or scripts.
7. No. Parsing only checks format and constructs metadata/content. It does not establish safety or trustworthiness of executable code.
