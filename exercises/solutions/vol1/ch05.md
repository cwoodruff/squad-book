# Chapter 5 Solutions

## Exercise Solutions

1. A more specific validation work type should be routed to the member best qualified to own API validation, provided that member is in the roster. A specificity rule can be expressed in the routing table with its own examples. The SDK compiler prioritizes more specific typed work-type rules, but an LLM reading Markdown is not a formal glob engine; state the distinction and validate the actual host's behavior.
2. A compatible sample manifest is:

   ```json
   {
     "machine": "tasktrack-worker",
     "capabilities": ["browser", "docker"],
     "missing": ["gpu"],
     "lastUpdated": "2026-10-27T00:00:00Z"
   }
   ```

   An issue labeled `needs:browser` and `needs:gpu` is skipped because all requirements must match and `gpu` is missing. In the v1.1.0 implementation, if no manifest can be loaded, the opt-in filter lets the issue pass through rather than blocking it.
3. “What port is Tasktrack on?” is Direct if the coordinator has the answer in context. A README typo is Lightweight: one small, scoped change. API validation is normally Standard because it needs the code and tests. An end-to-end due-date feature across API and UI may require Full if those are independently deliverable areas; one accountable owner still coordinates the work. Classify from scope and context, not elapsed-time promises.
4. In an already squadified project, a user can ask a personal agent for advice; the personal agent is read-only and a project agent implements approved changes. In a project without its own `.squad/`, `squad consult` copies the personal squad into an isolated local consult setup and offers selected generic learnings for explicit extraction. The CLI workflow requires a Git repository and refuses a project that already has `.squad/`.
5. The article shows a JSON array, but the SDK reads a `MachineCapabilities` object and accesses `capabilities.capabilities`; a bare array does not provide that property. Use `.squad/machine-capabilities.json` or `$SQUAD_HOME/machine-capabilities.json` with top-level `machine`, `capabilities`, `missing`, and `lastUpdated` keys (and optional `podId`).

## Quiz Answers

1. Routing answers **who** owns the work; response mode answers **how much agent coordination/context** the request needs.
2. `workType`, `agents`, optional `examples`, and optional `confidence`.
3. Every `needs:*` value on the issue must be present in the manifest's `capabilities` array.
4. The issue passes through the opt-in capability filter; an absent manifest does not block it.
5. Direct is no-spawn. Lightweight still spawns one agent with reduced context.
6. Personal-agent consultation (personal expert advises, project agent executes) and the CLI `squad consult` workflow (isolated copy of a personal squad in an external project, with optional extraction).
7. No. The inspected `SquadCoordinator.handleMessage()` does not call `selectResponseTier()`.
8. `--clean` deletes the project `.squad/` directory. Since consult also adds the agent prompt to `.git/info/exclude` and creates `.github/agents/squad.agent.md`, verify those separate local artifacts rather than assuming a total uninstall.
