# Chapter 12 Solutions

## Exercise Solutions

1. A typo fix is mechanical/fast; an ordinary API implementation is standard; a security review is premium under quality-first. A cheaper model may save on the initial completion but cost more if it misses an authorization edge case and triggers multiple rounds of diagnosis, repair, and review.

2. Fenster uses `gpt-5.3-codex`, because the persistent per-agent override is above the session model and global default. Clearing the Fenster override makes the session model `claude-sonnet-5.5` take precedence over the global default. If there is no session model, the global `claude-opus-5.5` would apply before charter/task-aware selection.

3. Report five of seven attempted turns (71.4%) have recorded usage, and provide recorded totals as partial estimates. Do not claim those totals are the complete session spend or infer that the two unrecorded attempts cost nothing. Investigate whether those turns failed before usage capture and compare with provider-side reporting if exact spend matters.

4. At 150/1000 = 15%, the state is amber; only priority 0 can proceed. At 40/1000 = 4%, the state is red; no priority may proceed under `shouldProceed()`.

5. Limit concurrency at the dispatch layer; classify priorities and stop/defer lower-priority work during amber/red; on 429 respect reset information and apply bounded exponential retry with jitter; ensure retried work is idempotent and report when work is paused. A shared JSON pool is not an atomic distributed allocator: multiple processes can race between checking and consuming quota. Use a real lock/central coordinator or lower concurrency.

6. The sample demonstrates response-tier selection and cost accounting with simulated or sample task data; it is not proof of a CLI quota cap or of automatic cost tracking for every production call. `squad cost` reads its usage ledger and shows coverage; it reports estimates, not an invoice or hard spend control.

## Quiz Answers

1. User one-spawn override → persistent config (per-agent/global) → session model → charter preference → task-aware selection → profile default. Availability fallback occurs after the base choice.
2. No. Explicit user/config/session/charter choices are not rewritten by the economy profile.
3. It refreshes/diagnoses the model catalog from available sources. It does not choose or set the current model or edit model preferences as a selection command.
4. 120 seconds by default; prediction needs at least three samples.
5. It estimates consumption using the first-to-last remaining-quota change over elapsed time, not a least-squares linear regression.
6. Only green. Amber permits only priority 0, and red permits none.
7. No. `CostTracker` accumulates usage; `squad cost` reports estimates from the ledger (or legacy logs), not a provider invoice.
8. Check and consume are not one atomic reservation across processes. Two clients can both observe unused allocation and consume beyond it unless a separate synchronization mechanism exists.
