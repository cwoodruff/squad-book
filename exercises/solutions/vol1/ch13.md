# Chapter 13 Solutions

## Exercise Solutions

1. `important` is intended to suppress rounds with no nonzero board counters. However, the v1.1.0 watcher does not pass `notifyLevel` into either `reportBoard()` call, and the reporter falls back to `all`; test the installed version or use a wrapper/logging policy rather than relying on suppression.
2. Set both `teamId` and `channelId` under `communications.adapterConfig["teams-graph"]`. `postUpdate()` returns a composite thread ID in the form `teamId|channelId`, which `pollForReplies()` uses to identify the channel.
3. One safe rewrite is:

   ```typescript
   import { createCommunicationAdapter } from '@bradygaster/squad-sdk';

   async function send(root: string, update: { title: string; body: string }): Promise<void> {
     const adapter = await createCommunicationAdapter(root);
     await adapter.postUpdate(update);
   }
   ```

   A production caller should also decide how to catch configuration, authentication, and network failures.
4. An MCP webhook route is typically one-way: an agent invokes a tool and an external MCP server forwards an alert. The Teams Graph adapter is an SDK communication interface that can post updates and poll messages from a chat or channel. Use the former for a simple delivery alert; use the latter when an SDK caller needs to read human replies.
5. `NOTIFY_COMPLETE` is an example environment variable for a notification MCP server, not a Squad config key. Unless that particular server documents the variable and receives it through its MCP configuration, Squad will not interpret it.

## Quiz Answers

2. No. Watch levels affect Ralph's board-report output, not Graph messages sent by an adapter.
3. `teams-graph`.
4. Both `teamId` and `channelId`.
5. Add `await` to the factory call and make the surrounding function asynchronous (or move adapter setup into an async initialization function).
6. No. It clears local in-memory and cached token state; it does not revoke the server-side token.
7. A self-chat ID is ambiguous. The adapter requires an explicit `chatId` rather than choosing an arbitrary one-to-one chat.
