# Chapter 6 Solutions

## Exercise Solutions

1. **Build a dependency graph.** Backend storage and endpoint support, frontend presentation, unit tests within each component, and docs can often proceed concurrently if the label model is fixed first. Agree on label representation (for example, an array of strings), normalization/validation, request and response shape, and whether labels are optional. Cross-component integration tests and final documentation review should follow the contract and implementation. If the schema is undecided, run a design decision first rather than letting each agent invent a different field.

2. **Choose state strategy.** Worktree-local is appropriate for an experiment that should not alter the main team's mutable context. It lets the branch carry an isolated configuration and logs. If the purpose is to test how the shared team routes work across branches, use main-checkout/shared state deliberately and understand that all worktrees will see its mutations.

3. **Spot a hidden conflict.** Git merges different files without conflict, but the API may return one field name while the UI reads another. Establish the shared field contract before parallel implementation, assign the contract or shared schema to one owner, and have both agents state which request/response field they implement. Add integrated tests that exercise the client against the API.

4. **Plan scratch retention.** Scratch contents can be removed by the watch cleanup capability and are ignored by Git, so they are not a durable handoff. Promote the accepted schema to a documented, version-controlled location such as the project's API contract or source directory, or attach it to the relevant issue/PR according to team policy. Keep only reproducible intermediate files in scratch.

5. **Recover safely.** Inspect the worktree status and diff; ask the agent to finish or commit the intended changes on its branch; if the work cannot yet be committed, preserve it (for example by making a safe patch or branch commit) before integrating. Merge the branch from the main checkout, resolve conflicts manually while retaining intended changes, run the tests, confirm the worktree is clean, then remove it without `--force`. Never delete or force-remove a dirty worktree just to unblock cleanup.

## Quiz Answers

1. Background mode describes when/how the coordinator runs independent agent sessions. A Git worktree is a separate checked-out directory and branch. One does not automatically create the other.
2. Use sequential execution when a task depends on a previous output, a reviewer gate must complete, or shared assumptions/files need to be established first.
3. The Copilot App `SessionSpawnBackend` defaults to five simultaneous active or starting sub-sessions. It rejects over-cap spawns; it does not configure a queue. Other backends can differ.
4. No. Worktrees have separate working directories, indexes, and checked-out branches, although they share repository storage.
5. The absolute `.squad/` directory path (the Squad root), not the repository root.
6. Union merge applies only to configured append-only files and combines lines; it neither prevents overlaps nor resolves semantic disagreements in arbitrary source files.
7. Confirm required changes are committed or otherwise preserved, the working directory is clean, and the integrated result has been tested. Remove without force.
