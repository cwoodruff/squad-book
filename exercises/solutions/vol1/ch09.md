# Chapter 9 Solutions

## Exercise Solutions

1. Use frontmatter such as `configured: true`, `interval: 10`, `timeout: 5`, and a clear description. The body should state: inspect at most three open issues labeled `squad`; report missing goal, acceptance criteria, and tests; make no changes to issues, labels, code, branches, or PRs; stop when the information is insufficient. In v1.1.0, `configured: false` selects onboarding messaging but does not stop execution, so read-only behavior must come from the prompt, permissions, and chosen agent environment.
2. `squad watch --interval 10` polls and triages/reports by default. Adding `--execute` enables spawning Copilot work on actionable issues. Before that, require a test repo/branch, least-privilege auth, explicit issue scope, a bounded timeout and concurrency, logging, human PR review, and a reliable Ctrl+C/stop plan. Confirm `execute` is not enabled through `.squad/config.json` unexpectedly.
3. One initial attempt plus one retry gives **two attempts**. With `backoffSeconds: 5`, the retry waits **5 seconds**. The due evaluator returns false for event triggers because an external event dispatcher, not the polling clock, is responsible for firing them.
4. `RalphMonitor` tracks each observed agent's session ID, status, last activity, optional task, and milestones, along with a last health-check timestamp and observations array. It subscribes to `session:created`, `session:destroyed`, `session:error`, and `agent:milestone`. `stop()` writes JSON only if `statePath` is configured. This module alone does not substantiate weekly archive retention, productivity trend analytics, or a 24/7 cloud service.
5. The schedule manifest only declares an entry; `squad schedule run` constructs `LocalPollingProvider`. In that provider workflow and Copilot tasks return stub results. The SDK's `GitHubActionsProvider` generator creates workflow YAML, but current generated content echoes a task reference rather than dispatching it. Inspect the provider implementation and generated workflow file, then verify an actual workflow run before relying on automation.
6. A sensible rollout starts with a read-only Watch run and report review; then a single low-risk issue with `--execute`, `--max-concurrent 1`, a conservative timeout, logging, and a human-reviewed PR; only after observing successful cycles should the team expand eligible labels or concurrency. Keep Ctrl+C and the appropriate process stop procedure known, retain branch protections, and review all external effects at every stage.

3. Less read-only; it enables agent execution and possible repository changes.
4. It prints an onboarding-mode banner; it does not prevent the loop from executing.
