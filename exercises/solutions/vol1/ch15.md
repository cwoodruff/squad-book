# Chapter 15 Solutions

## Exercise Solutions

1. **Classify the knowledge.** An API style rule that affects every agent belongs in `.squad/decisions.md` (or its decision inbox before merge). A backend specialist’s verified status-code detail belongs in that agent’s `history.md` unless it becomes a team-wide convention. A repeatable release procedure belongs in a skill. This afternoon’s test failure is transient; keep it in task/session context or an operational log unless it reveals a durable regression pattern worth preserving.

2. **Draft a decision.** One suitable entry is: “Keep the Tasktrack API dependency-free; preserve `node:http` and `node:test` unless the team explicitly revisits the design.” The rationale is that Tasktrack demonstrates a zero-dependency API running directly on Node 22.18+. If a prior decision allowed a web framework or test framework, the new entry should name and supersede it rather than leave conflicting rules active. The exact file format should follow the team’s convention; SEM metadata is optional design guidance, not a v1.1.0 runtime requirement.

3. **Review a history note.** “`PATCH /tasks/:id` accepts only `todo`, `doing`, or `done`; `createApp()` in `api/src/app.ts` returns HTTP 400 for an invalid status and 404 for an unknown task id. Confirm this contract in `api/test/app.test.ts` before changing it.” This includes the observed behavior and its evidence. It avoids vague wording and does not imply a fix without identifying one.

4. **Read the SEM proposal critically.** Useful fields include `type` (entry category), `timestamp` (chronology), `author` (provenance), `scope` (audience), `summary` (scan-friendly statement), and `rationale` (why). The format document is explicitly a draft. The v1.1.0 governed memory store writes its own frontmatter fields and does not parse SEM; the stable CLI has no `convert-memory` command. Therefore, the fields are useful to humans but not guaranteed to be validated or interpreted by the release.

5. **Reason about governed memory.** A safe local fact usually classifies as `LOCAL` and may be stored. A directive beginning with “Always” or “Never” is likely `POLICY` and may be written to the policy inbox. CI status is `TRANSIENT` and should not be persisted as durable memory. An API token should match a forbidden credential pattern, be rejected, and not be written. Classification is pattern-based and incomplete, so do not treat a permitted result as a security guarantee.

2. Inbox entries are proposals awaiting review and consolidation; they may conflict, duplicate one another, or need validation before becoming active rules.
3. The named agent is the primary reader. Its history preserves domain-specific context for that agent.
4. No. SEM is an internal draft; `LocalMemoryStore` writes a YAML-frontmatter file with a different schema.

6. No. Local search performs case-insensitive substring matching over the title and file content.
