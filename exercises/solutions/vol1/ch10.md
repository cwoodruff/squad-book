# Chapter 10 Solutions

## Exercise Solutions

1. Example policy: `dueDate` is either absent or a real calendar date in `YYYY-MM-DD`; reject impossible dates such as February 31. On create, omitted due date becomes `null`. On PATCH, omitted `dueDate` means unchanged and explicit `null` clears it. Tags are trimmed, non-empty strings, deduplicated case-insensitively while preserving the first spelling; omitted tags on PATCH means unchanged, `[]` clears them, and a non-array or any non-string/blank value is HTTP 400. Ask the product owner to decide whether past dates are permitted, whether tag case is preserved in display, and whether tag count/length is constrained. State those decisions in the PRD before treating them as acceptance criteria.

2. One possible graph:
   - Define the API contract and edge cases (no dependencies).
   - Add TaskStore fields/defaults and date/tag normalization (depends on contract).
   - Add POST/PATCH validation and API tests (depends on contract and TaskStore behavior).
   - Add UI create/display controls (depends on the agreed API contract; can proceed with API code if the JSON contract is fixed).
   - Run integration/regression checks (depends on API and UI slices).

   Keep each issue small enough to complete and review separately. Do not mark the UI as dependent on API implementation if both sides can independently build against the agreed contract.

3. Use `.squad/workstreams.json` for the v1.1.0 SDK resolver, despite the feature page's `.squad/streams.json` wording. Define each entry with `name` and `labelFilter`; set optional folders and workflow. Set `SQUAD_TEAM=api` or `SQUAD_TEAM=web`, or run `squad subsquads activate api` / `... web`. The environment variable wins over the local file; one-entry configs auto-select. `folderScope` is an agent hint, not an OS-level or tool permission boundary. Also verify the actual watch path uses the stream filter before assuming labels scope all triage.

4. “Why does task creation return 400?” and “Review test coverage for tag normalization” are read-oriented diagnosis/review and are plausible fleet candidates. “Add dueDate validation” is write-heavy and belongs on the sequential/task implementation path. Sending it through `/fleet` risks creating competing edits or confusing issue comments with implemented and tested code. Hybrid mode should be the safer choice when the issue list mixes both kinds.

5. Example `.squad/config.json`:

   ```json
   {
     "watch": {
       "execute": true,
       "dispatchMode": "hybrid",
       "fleet-dispatch": true,
       "interval": 10,
       "maxConcurrent": 1,
       "timeout": 30
     }
   }
   ```

   Confirm Copilot CLI and `gh` are available/authenticated. Start with a small set of read-only issues, inspect preflight and watch output, and verify issue comments and diffs afterward. Setting `dispatchMode` without enabling the capability can result in a warning and no batching. Do not assume the documented performance multiplier applies to your queue.
