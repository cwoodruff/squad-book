# Chapter 8 Solutions

## Exercise Solutions

1. The v1.1.0 detector recognizes GitHub and Azure DevOps URL formats and defaults unknown remotes to GitHub; its adapter factory constructs GitHub or ADO adapters, not GitLab. A team can use `glab` directly with a human-controlled workflow, or build/install an explicitly verified GitLab adapter/integration before automating. It should not let an unknown GitLab remote silently fall through to GitHub behavior.
2. ```json
   {
     "ado": {
       "org": "YOUR_ORG",
       "project": "Platform Intake",
       "defaultWorkItemType": "Scenario"
     }
   }
   ```
   Merge this into the existing `.squad/config.json`; area and iteration paths are omitted so ADO project/team defaults apply.
3. The adapter splits the semicolon-separated `System.Tags` string into a trimmed array when reading. To add a tag, it reads existing tags, removes an exact duplicate, appends the requested tag, then writes the full field back. Reading first preserves unrelated tags; blindly replacing the whole string could erase work ownership, categorization, or other automation metadata.
4. The helper falls back to a small list of common types when its CLI call fails, and validation is fail-open when the type list cannot be retrieved. The result is a convenience fallback, not authoritative evidence from the live project. Re-run the query with valid credentials and confirm the type is enabled. Before accepting a proposed mapping, verify the live project’s enabled types and required fields with an authenticated CLI query; then test the exact adapter call in a non-production project.
5. The stable SDK includes Planner and a separate `WorkItemSource`/hybrid configuration, making repository hosting and task tracking distinct; the PRD centers its mapping on GitHub and ADO. The implementation also has optional adapter operations and separate communication adapters, rather than one guarantee that every operation is uniform. Check the shipped factory and adapter methods, then test the exact `gh`/`az` identity, scopes, remote parsing, config, and operation in a test project before production use.
6. Listing an ADO work item and adding an ADO tag belong to the platform adapter. Creating a pull request is also a platform-adapter operation. Creating a programmatic Copilot session belongs to `SquadClient` (or its pooled facade), a separate execution/session API rather than a work-tracking contract.
