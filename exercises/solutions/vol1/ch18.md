# Chapter 18 Solutions

## Exercise Solutions

1. “Always test malformed JSON” is a directive because it states a persistent expectation. Capture it through configured governed memory/state, and consider a tracked test-policy or CI change if the requirement must be enforced. “Add malformed-JSON tests today” is a work request; route and implement it. “Why does malformed JSON return 400?” is a question; answer it directly. A mixed message such as “Always test malformed JSON, and add the test now” should both capture the directive and route the task.

2. One valid definition is:

   ```markdown
   ## Tasktrack API Contract Review

   | Field | Value |
   |-------|-------|
   | **Trigger** | auto |
   | **When** | before |
   | **Condition** | Multiple agents will change a shared Tasktrack API endpoint or request/response contract |
   | **Facilitator** | lead |
   | **Participants** | all-relevant |
   | **Time budget** | focused |
   | **Enabled** | ✅ yes |

   **Agenda:**
   1. State the endpoint contract and affected callers.
   2. Identify success, invalid-input, and missing-resource cases.
   3. Assign implementation and test ownership.
   4. Record unresolved risks and decisions.
   ```

3. The coordinator must not assign Ada to revise or contribute as advisor/co-author. It should ask the reviewer to name a different qualified agent or escalate for a new specialist/user decision. If the next revision is rejected, that revision's author is locked out too. Select a third eligible agent or escalate if none remains.

4. A prompt-level rule explains expectations, but can be overlooked. A test verifies behavior for cases encoded in it; CI can require that test suite to pass. A hook can block specific write actions if correctly activated and scoped. Branch protection can prevent merging when required status checks or approvals are missing. A strong combination is a clear directive plus tests/CI and branch protection, with reviewer protocol for substantive rejection. Each mechanism has a distinct purpose; a hook is not a substitute for a complete test contract.

5. The template proposes weekly review when no retrospective log exists in the previous seven days, and says action items should become GitHub Issues labeled `retro-action`. It refers to `retro-enforcement` and `Test-RetroOverdue`, neither of which was found as a shipped skill in the inspected v1.1.0 source. Before claiming weekly enforcement, verify that an actual installed workflow/skill implements the check; otherwise describe the block as a template proposal.

## Quiz Answers

1. A directive is a persistent expectation for future team behavior; a work request asks for a concrete task now.
2. Do not create a local or gitignored Markdown proposal as a persistence fallback or claim it was saved. Acknowledge it honestly and use the configured governed state tool when available.
3. After routing and before work-agent spawn, so the facilitator and participants can use the routed context and the work prompts can include its summary.
4. `all-relevant`, `all-involved`, or a comma-separated set of named agents.
5. No. Strict lockout prohibits the original author from contributing in any form to that revision.
6. Escalate to the user for a manual fix, new specialist, or other explicit resolution; do not silently re-admit a locked-out agent.
7. The SDK hook holds its registry in process memory; it does not itself persist state across process or session restarts.
