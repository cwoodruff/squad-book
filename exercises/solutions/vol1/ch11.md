# Chapter 11 Solutions

## Exercise Solutions

1. Due-date validation can be green when the contract is settled and API tests are clear: it is bounded and testable. Tag UI integration is yellow because it spans input, display, and user experience details and should receive a Squad member review. Storage architecture redesign is red because it is cross-cutting and affects system design beyond a bounded coding-agent issue.

2. Example issue:

   ```markdown
   ## Goal
   Validate Tasktrack due dates and tags at the API boundary.

   ## Acceptance criteria
   - Accept a real YYYY-MM-DD date or null to clear a date.
   - Reject impossible dates and blank/non-string tags with HTTP 400 and a JSON error.
   - Trim and deduplicate tags case-insensitively.
   - Preserve existing title validation, status updates, and unknown-ID 404 behavior.
   - Add tests in api/test/app.test.ts and pass `npm test`.

   ## Out of scope
   Do not change the browser UI or add persistence.
   ```

   This issue carries its own contract and scope even if the PRD or conversation is unavailable to the asynchronous worker.

3. Add label → Actions workflow starts → token preflight succeeds → assignment API accepts request and returns `copilot-swe-agent[bot]` → workflow posts acknowledgment → Copilot session or linked draft PR appears → reviewer inspects diff/tests. The actual evidence that a session started is a linked Copilot session or evidence of Copilot activity on a linked draft PR—not the label, API response, assignee, or successful workflow alone.

4. `squad rc` provides a browser chat bridge and ACP relay; it uses the SDK RemoteBridge and remote UI. `squad start` launches a local Copilot process in a PTY and mirrors terminal I/O. `rc` uses the Copilot CLI ACP path and optional authenticated devtunnel; `start` needs `node-pty` and can optionally tunnel the PTY mirror. Use `rc` for a chat-oriented remote browser interaction and `start` when you need to watch/control the same terminal. A tunnel exposes a privileged process with repository context and potentially powerful tools; authentication and redaction reduce risk but cannot eliminate it.

5. Inspect the issue first for a linked Copilot session, draft PR, or activity. Check the Actions log for the exact failed step without printing the secret. If the assignment API may already have accepted the request, avoid blindly re-running it; confirm with GitHub state or ask a repository administrator to verify. If there is no handoff, check secret presence, label, workflow permissions, and issue state, then retry through the authorized workflow only. Rotate the PAT if it was exposed.

## Quiz Answers

1. No. `@copilot` uses the repository-level `copilot-instructions.md`, and its work is tracked by issues and PRs rather than a standard Squad charter/history.
2. The coding-agent bot cannot be assigned like a normal human account. The supported route in this setup is the `squad:copilot` label and the PAT-backed workflow.
3. `COPILOT_ASSIGN_TOKEN`, documented as a classic PAT with repository scope, stored as an Actions secret.
4. No. Verify a Copilot session linked to the issue or Copilot activity on a linked draft PR.
5. `squad rc` is the browser/ACP chat bridge; `squad start` is the PTY mirror.
6. The CLI's deprecation warning recommends using GitHub Copilot CLI directly (`gh copilot`).
7. Redaction is pattern-based and incomplete by nature; remote interaction has access to a local process and repository, so secrets and tools may still be exposed. Keep tunnels private, stop them when finished, and use trusted devices.
