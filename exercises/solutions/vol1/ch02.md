# Chapter 2 Solutions

## Exercise Solutions

1. A macOS developer with Node already installed can use npm (or Homebrew if they prefer a vendored runtime); a Windows runner that cannot access npm can use WinGet or the direct Windows bundle, depending on how much version control the CI needs; an air-gapped Linux runner should stage a verified archive from its internal artifact mirror. For a strict offline environment, ensure both the archive and its checksum data are staged internally.
2. The package-manager or installer update changes the installed `squad` executable. `squad upgrade` updates Squad-managed files in one initialized repository. User-owned team state such as agents, decisions, and histories is intended to be preserved by project upgrade.
3. Check shell resolution (`command -v squad` or `Get-Command squad`) and inspect the resolved path and version; then check whether an older installation precedes the updated one on `PATH`. Open a fresh shell if its environment has not reloaded.
4. Use VS Code for an edit where inline diagnostics and visible source are central; use `squad` for setup and diagnostics; use SDK-first mode for a reusable typed TypeScript team definition; choose Copilot CLI for a task requiring per-spawn model choices, since VS Code uses the selected session model. For a team mixing Copilot and Claude Code users, the Squad 2.0 preview is the option with multi-client support (`squad init --client ...`); because it is preview software, evaluate it in a disposable project first and keep 1.1.0 for everyone who only needs Copilot.
5. A correct preparation has the sample copied to a new directory, Git initialized with a commit, a clean worktree, five passing tests under Node 22.18+, and a `ch02-start` tag. The API tests cover the health response, task creation and listing, empty-title rejection, status updates with validation and unknown IDs, and deletion.
6. Edit `squad.config.ts` (or the discovered TypeScript config), then run `squad build` to regenerate the markdown. Add `squad build --check` to CI to validate generated files without writing.

## Quiz Answers

1. The install script, Homebrew cask, WinGet package, and direct release bundle vendor Node.js. An npm install does not; it needs Node 22.5+.
2. It pins the release tag to install; the default is the latest stable release.
3. `insider` carries the 2.0 preview (with `preview` as an alias); `latest` is stable (v1.1.0).
4. False. `squad upgrade` refreshes project-managed files; `squad upgrade --self` updates the CLI package itself.
5. GitHub Copilot CLI and VS Code with GitHub Copilot.
6. VS Code uses the session model selected in the model picker; the per-spawn model selection documented for the CLI is not available there.
7. No. The implementation documents doctor as diagnostic and exits 0 even when checks fail, so a human should read the report.
8. `squad.config.ts` (or `squad/index.ts`). `squad build --check` validates that the generated files match what is on disk without writing anything, which makes it suitable for CI drift checks.
