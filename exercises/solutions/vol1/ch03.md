# Chapter 3 Solutions

## Exercise Solutions

1. Tasktrack exposes `GET /health`, `GET /tasks`, `POST /tasks`, `PATCH /tasks/:id`, and `DELETE /tasks/:id`. Status values are `todo`, `doing`, and `done`. Existing tests cover health, task create/list, rejection of blank titles, status updates plus invalid status and unknown IDs, and deletion. Include the facts that the API uses `node:http`, TypeScript runs through Node’s built-in type stripping, tests use `node:test`, the UI is static HTML/JavaScript, and there are no runtime dependencies. Those facts steer the coordinator away from proposing Express, React, or a database without a reason.

2. `.squad/team.md` is the current roster, project context, and coordinator/member listing. `.squad/decisions.md` stores shared architectural decisions and directives. `.squad/agents/<name>/charter.md` is the active contract for a particular AI agent. `.squad/templates/charter.md` is a reusable template/reference used when creating charters; it is not the active role contract for an agent.

3. Example: “Inspect `api/src/app.ts`, `api/src/tasks.ts`, and `api/test/app.test.ts`. Do not modify files yet. Summarize the current routes, data model, and test coverage; identify one small improvement and explain its expected test. Keep the implementation on `node:http`, preserve zero runtime dependencies, and do not assume a framework or database.”

4. First verify `.github/agents/squad.agent.md` exists at the Git root and that Copilot can see it. Launch `copilot --agent squad` (or choose Squad from the client’s agent picker). The prompt resolves the team root and checks `.squad/team.md`; an empty Members section means Init Mode, not necessarily a failed init. Review and confirm the proposed roster; only then should specialist charters and routes be written. If the file is absent, check the project/Git-root location, monorepo placement, and init output.
