# Appendix G: SDK API Quick Reference

This appendix indexes the public API exposed from `packages/squad-sdk/src/index.ts` at v1.1.0. The entry point is a side-effect-free barrel; named declarations re-exported by its sub-barrels are public, while CLI-only command handlers are not. Type signatures below show callable shapes and principal input/output types; domain-specific option members remain defined in the exported interfaces. For exact generic constraints and overloads, use the v1.1.0 declaration files shipped with `@bradygaster/squad-sdk`.

## Source organization and non-root barrels

The root export is not the whole source tree. Two additional barrels help explain how the SDK separates parsing from runtime execution:

| Source | Responsibility |
|---|---|
| `packages/squad-sdk/src/parsers.ts` | Re-exports Markdown migration parsers, routing compilation and matching, charter parsing and validation, state charter serialization, and skill parsing. It contains no runtime implementation of its own. |
| `packages/squad-sdk/src/types.ts` | Re-exports types using `export type`; importing those types does not initialize a runtime. It includes parsed configuration, charter diagnostics, routing matches, adapter configuration, multi-squad configuration, and builder types. |
| `packages/squad-sdk/src/utils` | Internal helpers for bounded-concurrency mapping, line-ending normalization, filename-safe timestamps, and name slugification. These utilities support platform compatibility and predictable execution, rather than forming an independent agent framework. |

Use the package entry points listed below rather than importing a file merely because it exists in the repository. A source barrel and a published package subpath are different contracts: check the package's `exports` map before choosing an import path. In particular, deprecated workstream and stream aliases in the types barrel do not mean those older names are preferred over subsquad terminology.

## Root barrel map

The root barrel directly exports resolution helpers, config, onboarding/personal-agent helpers, casting, skills, response tiers, runtime configuration/constants/streaming/usage/context/cost/telemetry/offline/i18n/benchmarks/OpenTelemetry/rework/events, selected cross-Squad functions and types, marketplace, build, sharing, upstream, remote, streams, SDK builders, roles, platform, storage, memory, state backends, Git-ignore helpers, state collections, and archival IO. Thus the public API is broader than the callable examples in this guide. Important root aliases avoid name collisions: `RuntimeEventBus`, `BuilderRoutingRule`, `BuilderSkillDefinition`, and `BuilderSkillTool`. The root barrel explicitly selects symbols from `state-backend.ts` and `state/index.ts`; that file's other internal exports are not automatically root exports.

## Feature APIs and type-safe integration boundary

The public barrel also exports the adapters/client/runtime/coordinator/hooks/tools, Ralph, config-migration, model, preset, and parser surfaces named in the package export map. These are deliberately separated into subpaths so consumers can import a narrow capability. Key public areas include the adapter client and typed errors; coordinator routing/response support; hook registration/execution; tool contracts; Ralph triage, machine-capability and rate-limit utilities; preset discovery and application; model selection; config migration; and MCP/runtime event integrations. For a method-level inventory of these broad modules, the `export *` declarations in `src/index.ts` are the definitive list of entry barrels and the corresponding exported `.d.ts` files are the definitive signatures.

> **API stability:** The barrel can expand between releases. This quick reference describes v1.1.0 and intentionally directs readers to its declaration files for exact overloads rather than guessing signatures for every re-exported helper.

## Squad 2.0 (Preview) Client and Backend APIs

> **Preview:** The APIs in this section target `@bradygaster/squad-sdk` `v2.0.0-preview.2` (`insider`). They are preview contracts and may change before stable 2.0.0.

### Client projection and adapter subpath

Import the canonical host API from `@bradygaster/squad-sdk/client`. The `/clients` package path remains available as a deprecated alias to the same adapter exports; prefer `/client` in new code.

```ts
import {
  CLIENT_IDS,
  HOST_PROJECTIONS,
  CAPABILITY_TOKENS_BY_HOST,
  projectClients,
  installClients,
  uninstallClients,
  normalizeClientIds,
  assertPortableClients,
  createClientAdapter,
} from '@bradygaster/squad-sdk/client';
```

The public client surface is grouped by responsibility:

| Host contract | `HostProjection`, `ClientAdapter`, `AdapterHostKind`, `AdapterDescription`, `AdapterCapabilityProjection`, `ProjectWorkspaceProjection`, `AdapterSubmission`, `AdapterSubscription`, `ApprovalResponse`, `RuntimeBinding`, `CreateClientAdapterOptions`, `AdapterUnboundError`, `createClientAdapter` |
| Host identities and projection metadata | `CLIENT_IDS`, `ClientId`, `McpLaunchSpec`, `ClientContext`, `ProjectionFile`, `DispatchStrategy`, `TransportMode`, `ClientCapabilities`, `ApplyAction`, `ApplyResult`, `HOST_PROJECTIONS`, `CLIENT_ADAPTERS` (deprecated alias), `getHostProjection`, `getClientAdapter`, `parseClients`, `SQUAD_STATE_KEY`, `CODEX_AGENT_PATH`, `opencodeConfigPath` |

`CAPABILITY_TOKENS_BY_HOST` describes declared host capabilities; it is not by itself a runtime guarantee. The effective set is the intersection of client, backend, and policy capabilities. `normalizeClientIds` removes invalid persisted entries while preserving a report of rejected values; `assertPortableClients` is the strict validation form. `uninstallClients` removes managed projections and preserves unrelated user-authored bytes.

### Experimental backend subpath

`@bradygaster/squad-sdk/backend` is a separate, explicitly experimental entry point. From `types.ts`, it exports the run/task and protocol constants (`BACKEND_CONTRACT_STAGE`, `BACKEND_PROTOCOL_VERSION`, `BACKEND_CAPABILITIES`, `TERMINAL_RUN_STATES`, `ALL_CONTENT_PART_TYPES`); the backend contract and data types (`SquadBackend`/`IConversationBackend`, `BackendConfig`, `BackendStateStore`, `BackendConversation`, `BackendMessage`, `BackendEnvelope`, `BackendEventPage`, `BackendTurn`, `BackendAdmission`, `BackendHealth`, `BackendError`, `BackendErrorInfo`, `BackendErrorCode`, `NegotiatedCapabilities`, `ProtocolHello`, `BackendContentPart`, `ExtensionBag`, `ReadEventsOptions`, `CreateConversationOptions`, `RunState`, `TaskState`, `BackendStream`, `BackendCursor`, `LeaseEpoch`, and `CapabilityFlag`); and approval/harness types (`ApprovalScope`, `ApprovalRequest`, `HarnessApprovalRequest`, `ApprovalRecord`, `ApprovalResponse`, `HarnessCapabilities`, `HarnessSubmission`, `HarnessEvent`, `HarnessEventEnvelope`, `HarnessDescriptor`, `HarnessAdapter`, and `HarnessRegistry`). It also exports `intersectCapabilities` and `partsToText`. The implementation exports are `DefaultHarnessRegistry`, `extensionNamespace`, `validateExtensions`, `LocalSquadBackend`, `MemoryStateStore`, `createFileStateStore`, `createStateBackendStore`, `DurableHttpSquadBackend`, `validateBaseUrl`, and `createSquadBackend`, with their option/store types (`LocalSquadBackendOptions`, `FileStateStoreOptions`, `StateBackendLike`, `StateBackendStoreOptions`, and `DurableHttpOptions`).

This barrel is intentionally not re-exported from the SDK root. `DurableHttpSquadBackend` callers provide an explicit `baseUrl` (HTTPS, except localhost) and optional `token`; the CLI's `SQUAD_BACKEND_URL` and `SQUAD_BACKEND_TOKEN` are not SDK defaults. The preview bridge exposes transcript/event operations but does not ship a harness that executes agent turns.

### Removed 1.x profile exports

The 2.0 root barrel no longer exposes the personal/consult helpers: `resolvePersonalSquadDir`, `ensurePersonalSquadDir`, `isConsultMode`, `resolvePersonalAgents`, `mergeSessionCast`, `PersonalAgentMeta`, and `PersonalAgentManifest`; the `@bradygaster/squad-sdk/agents/personal` subpath was removed as well. The 1.x multi-Squad runtime exports `discoverSquads`, `readSquadRegistry`, `writeSquadRegistry`, `findSquadByName`, `CrossSquadIssueOptions`, `CrossSquadIssueResult`, and `CrossSquadWorkStatus` are also absent from the 2.0 root barrel. Do not treat the remaining upstream discovery API as a drop-in replacement for those removed exports.
