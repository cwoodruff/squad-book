# Part II — Working with Squad Daily {.unnumbered}

Part II is about the habits of everyday use. It begins with how work reaches the right agent, then moves through parallel execution, GitHub and other hosts, the Ralph loop, PRD-driven streams, the coding agent, cost control, notifications, and keeping an installation tidy and current. It sits right after Part I because these are the skills you need before memory, governance, or operations make sense.

Read it in order if you are new; if you already use Squad, pick the chapters that match your daily friction.

- **Chapter 5: Routing, Capability Routing, and Response Modes** How requests find an agent.
- **Chapter 6: The Parallel Work Model** Running several agents at once without collisions.
- **Chapter 7: GitHub Workflow and Issue-Driven Development** Issues, labels, and pull requests.
- **Chapter 8: GitLab and Azure DevOps** Using Squad outside GitHub.
- **Chapter 9: Ralph, the Loop, and Scheduling** The work monitor and unattended cycles.
- **Chapter 10: PRD Mode, Streams, and Fleet Dispatch** Turning requirements into parallel streams.
- **Chapter 11: Copilot Coding Agent and Remote Control** Delegating to cloud agents and steering remotely.
- **Chapter 12: Models, Cost, and Rate Limiting** Choosing models and controlling spend.
- **Chapter 13: Notifications and Team Communication** Keeping humans informed.
- **Chapter 14: Cleanup, Upgrades, and Migration** Maintaining and upgrading a v1.x setup.

**Tasktrack:** by the end of Part II your squad takes issues, routes and parallelizes work, runs the loop, and you can upgrade it safely.
